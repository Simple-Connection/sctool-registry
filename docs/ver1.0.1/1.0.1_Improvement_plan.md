## 1. Purpose

Version `1.0.1` consumes the authenticated Registry access boundary established by:

```text
docs/REGISTRY_ACCESS_V1.md
docs/REGISTRY_CONTRACT_V2.md
docs/ARTIFACT_DELIVERY_V1.md
policy/registry-policy.json
```

The version goal is to make the GitHub-authenticated Registry access model consumable by the SCTool SDK/CLI and to replace transitional flat artifact URL metadata with a structured, machine-validated delivery descriptor without taking ownership of Simple Connection desktop/UI or repository lifecycle classification.

## 2. Version branch rule

All Registry sessions belonging to this distribution contract version remain on:

```text
dev/1.0.1
```

Session completion does not cause a merge to `main`.
The branch is merged only after every approved `1.0.1` session and the version-level acceptance gate are complete.

A session blocked only by an external validation obligation may stop owning the active work pointer, but it remains a version merge blocker until the external evidence closes.

## 3. Documentation layout

```text
docs/ver1.0.1/
├─ 1.0.1_Improvement_plan.md
└─ session_document/
   └─ ver.1.0.1_P{N}_{topic}.yaml
```

Rules:

1. This file owns version purpose, `current_session`, session index, acceptance, and merge state.
2. Detailed scope, implementation evidence, validation, blockers, and closeout state live in the session YAML.
3. Session YAML files are created only when that session is approved to begin.
4. Primary session IDs are `P1`, `P2`, ...; work-unit numbering is session-local and starts at `W1` for each primary session.
5. Registry session authority remains in this repository even when implementation code is physically stored in another repository.
6. `current_session: null` means no approved Registry session is actively executing; it does not mean version acceptance is complete.

## 4. Responsibility boundary

### In scope

- consuming `REGISTRY_ACCESS_V1` in the SCTool SDK boundary;
- GitHub CLI credential-store identity handling;
- canonical GitHub identity resolution;
- inherited `GH_TOKEN` / `GITHUB_TOKEN` isolation;
- private Registry artifact repository authorization probing;
- fail-closed access-state handling;
- Registry package descriptor and artifact-delivery metadata contracts;
- backend-neutral artifact content/integrity metadata;
- authenticated GitHub Release asset locator schema and validation;
- Registry JSON/schema/cross-field validation;
- Pages metadata compatibility evidence;
- cross-repository evidence needed to prove the Registry contract is consumable.

### Out of scope

- Simple Connection renderer/UI design;
- Simple Connection installer UX or product release-session planning;
- Simple Connection PTSIP lifecycle classification or profile migration;
- production Root trust activation or `trust/trust.json` issuance;
- per-device entitlement, commercial licensing, or application attestation;
- exposing, persisting, or extracting GitHub tokens;
- artifact binary download implementation in P1/P2;
- package/channel resolution behavior changes in P1/P2;
- activating additional artifact delivery backends in `1.0.1`.
