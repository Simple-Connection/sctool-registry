## 1. Purpose

Version `1.0.1` is the implementation cycle that consumes the authenticated Registry access boundary already established by:

```text
docs/REGISTRY_ACCESS_V1.md
docs/REGISTRY_CONTRACT_V2.md
policy/registry-policy.json
```

The version goal is to make the approved GitHub-authenticated Registry access model consumable by the SCTool SDK/CLI without taking ownership of Simple Connection desktop UI, installer UX, or production trust activation.

## 2. Version branch rule

All sessions belonging to this distribution contract version use one persistent branch:

```text
dev/1.0.1
```

Session completion does not cause a merge to `main`.

The branch is merged only after all approved `1.0.1` sessions are complete and version-level acceptance has passed.

## 3. Documentation layout

The version uses one improvement-plan index and one YAML document per implementation session:

```text
docs/ver1.0.1/
├─ 1.0.1_Improvement_plan.md
└─ session_document/
   └─ ver.1.0.1_P{N}_{topic}.yaml
```

Rules:

1. This file owns only version-level purpose, session index, acceptance, and merge state.
2. Detailed implementation scope, exclusions, validation evidence, completion criteria, and next action belong in the session YAML.
3. A session YAML is created when that session is approved to begin; placeholder documents for unstarted sessions are not pre-generated.
4. Session identifiers use `P1`, `P2`, `P3`, ... . A sub-session may use `P1.1`, `P1.2`, ... only when an already approved primary session must be split.
5. Session files remain on `dev/1.0.1` until the entire version is complete.

This organization is adapted from the version/session documentation pattern used by `Kinirin/ERP_suver`, while keeping the Registry hierarchy intentionally shallower.

## 4. Responsibility boundary

### In scope

- consuming `REGISTRY_ACCESS_V1` semantics in the SCTool SDK boundary;
- GitHub CLI credential-store identity handling;
- canonical GitHub identity resolution;
- inherited GitHub token override isolation;
- private Registry artifact repository authorization probing;
- fail-closed access-state handling;
- SDK/CLI machine-readable contracts and tests required by approved sessions;
- documentation necessary to hand the stable CLI contract to Simple Connection consumers.

### Out of scope

- Simple Connection renderer/UI design or download buttons;
- Simple Connection installer UX or package activation policy;
- production Root trust activation or `trust/trust.json` issuance;
- per-device entitlement, commercial licensing, or application attestation;
- exposing, persisting, or extracting GitHub tokens;
- changing Registry package ownership or immutable artifact identity rules without a separately approved session.
